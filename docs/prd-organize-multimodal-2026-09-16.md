## 0. 一句话

把病历整理从「确定性 OCR 当字符真值、LLM 只做辅助、关闭清单硬套 schema」改回、并做实成：

**每一页都把像素和电子字一起交给多模态模型，先写成完整 Markdown；结构化是对 Markdown 的开放投影。规则里没有的材料类型也必须全文落库，而不是被隔离或当成缺失项。**

整理要同时变得：**更快、更准、更省 token、更能消化未见过的报告。** 三件事必须一起成立；只砍步骤、不改主读取器，是假瘦身。

---

## 1. 背景：最初要做成什么样

`cancer-buddy-organize` 的产品任务是：患者或家属丢来一包 PDF / 照片 / 扫描件 / 检验单，整理成带出处的患者目录，供就诊准备、宣教、SMTB 等下游使用。它不替代医生，不推断分期、疗效、ECOG、治疗线。

最初对「怎么读这些材料」的设计意图是：

1. **多模态大模型是图片和扫描件的主读取器。** 病历现场材料大量是手机翻拍、合订本、屏幕截图、带章和手写的纸面。大模型对版面、表格、红圈、印章、手写的理解，明显强于 tesseract 一类通用 OCR。
2. **每一张图都直接给模型看**，而不是先调用 Python 包解析出一堆残字，再让模型在残字上猜。
3. 原生 PDF 上的电子字可以当对照，但**纸面（像素）同样要看**：章、手写、勾选、被圈出的阳性、被 pdftotext 打乱的栏，都在图上。
4. 整理的完整性由「原文是否被读全」保证，而不是由「有没有填进我们预先写好的 schema」保证。

这条意图在后续安全整改里被写反了。本次重构是把它写回来，并补上实践里暴露的另外两件事：流程过长、类型清单是关闭世界。

## 2. 现在实际跑成什么样

当前契约（`organize-contract.md` Extract、`organizer-prompt-phase1-ocr.md`、Penguin 绑定）规定：

> 确定性 OCR / 原生文本层优先；LLM 只做版面、纠错候选、语义标注。  
> 模型对同一张图再读一遍，**不算独立复读**。独立复读是 tesseract。  
> tesseract 与 vision 不一致 → 字段必须标 `needs_human_review`，vision 读对了也不能进 settled fact。

翻转发生在 2026-07-17 临床安全整改。CHANGELOG 原句：

> 病历整理改为原生/确定性抽取优先、LLM 仅作可审计辅助。

意图是「不要让 LLM 成为唯一字符真值、不要让模型编临床结论」。落地时把两件不同的事绑在了一起：

| 本应约束的 | 被误写成的 |
|---|---|
| 不要让模型编分期、疗效、治疗线 | 不要让模型读图 |
| 高风险字段要独立第二读 | 第二读必须是更弱的 tesseract |
| 原生文本层值得保留 | 有文本层就可以不看图 |

当前主路径实际是 18 步：

```
切片规划
  → Phase-1（OCR 主，vision 辅，高风险字段 tesseract 复读）
  → continuation
  → Phase-2 综合（14 桶 + 6 个 JSON schema）
  → coverage retry（checklist 不全就重派）
  → review_summary / review_flags / profile card
  → Phase-2.5 整档像素复读
  → PII 语义扫描（fail 就全量再扫，实测到过 5 轮）
  → 段D 模板 HTML + AGENTS.md + 段E 无关文件隔离
```

`SKILL.md` 约 67KB。文件自己承认：压缩后「产出 HTML」会活下来，「怎么产」会被摘掉。同样压力下，「先跑 tesseract」会活下来，「每张图用多模态完整读一遍」会被当成可省略的贵操作。

归档层是**关闭世界**：

- 14 个临床桶 + `bucket_taxonomy.json` 门禁，非清单目录直接 fail
- 19 份癌种 checklist 驱动 `missing_items.json`
- 规则外的报告类型容易进 `99_无关文件`，或从未被完整转写

## 3. 为什么要重构

### 3.1 主读取器选错了，识别率上不去

对扫描翻拍，tesseract 经常是 0 字节或乱码；真正能读的是 vision。契约却规定 OCR 是字符真值，LLM 只能提 `proposed_text`。两读一对不上就 `needs_human_review`。

结果是：**该认不出来的还是认不出来。** 不是模型没看见，是看见了也不准进档案。再扫一遍不会产生新的视觉信息，只会加 flag、加 token。

下游把内部质检噪音当成产品。2026-09-16 家属探针里，就诊准备包 9 条「请医生确认」中有 7 条是 OCR 小数点分歧（Hb 12 vs 112、TBIL 142 vs 14.2）。家属拿去问医生，医生也看不懂。

### 3.2 「便宜路径」没有省钱，时间被校验吃掉

PT-84E4A1445C 一次完整整理（`PT-84E4A1445C_token_cost.xlsx`，DSH 87 会话、口径见该表第 6 页）：

| 环节 | token | 占整理 | 模型步 |
|---|---:|---:|---:|
| Phase-1 摄取（含读图） | 99.3M | 51.8% | 691 |
| 复核门禁（忠实度 / PII / provenance） | 47.8M | 24.9% | 321 |
| Phase-2 综合 | 23.7M | 12.4% | 80 |
| 编排 | 12.6M | 6.6% | 74 |
| 段D + 收尾 | 8.3M | 4.3% | 54 |
| **整理合计** | **191.7M** | 100% | **1220** |

OCR 专项表自己的结论：

> 确定性 OCR（pdftoppm+tesseract）消耗 **0 LLM token**；token 花在模型视觉读图、逐条转写与修订留痕上。

tesseract 跑了 284 次 CLI / 77 页，token 是 0；真正烧钱的是 `read_image` 321 次 + 转写留痕。便宜路径没有替代贵路径，它叠在贵路径前面。

扫描件分片尤其说明问题：

| 分片 | 材料 | read_image | OCR CLI | token | 表内说明 |
|---|---|---:|---:|---:|---|
| s2 | 合订本 p1–13，手机翻拍 | 82 | 19 | 22.2M | 织物纹理，tesseract 原样失败 |
| s3 | 合订本 p14–26，含横置心电图 | 62 | 78 | 23.0M | OCR 前还要旋转 |
| s4 | 合订本 p27–39，钼靶截图 / 白页 | 107 | 113 | 30.6M | 最贵单块，朴素 OCR 返回 0 字节 |
| s6 | MRI + 超声照片 | 2 | 18 | 3.7M | 摩尔纹，OCR 大面积崩，主要靠视觉 |
| s1 / s5 | 原生文本层 PDF | 31 | 29 | 19.8M | 已有 pdftotext，仍读图做版面复核 |

扫描件四块 79.5M，占整理 41%。这些页上 tesseract 基本是废的，但契约仍要求先跑它，再拿它否决 vision。

校验循环再吃一截：

- Phase-2.5 整档像素复读：19.4M / 132 步
- PII 语义扫描 r1–r5：25.0M / 176 步
- OCR 相关合计（Phase-1 + 2.5）：118.7M = 整理的 62%

墙钟：完整整理 1.5–4 小时。增量更夸张——一份 **7 行纯文本化验单** 仍走 4 个 worker，**30 分钟 / 7.8M token**（2026-09-16 probe 4）。

### 3.3 关闭世界，规则外材料整理不了

真实病历不会只出现在 14 桶和 19 份癌种清单里。肠道菌群、骨密度、中医门诊、新基因公司面板、外文 PET-CT、带手写的出院带药单——只要不在规则里，当前流程倾向于：

- 转写不完整（Phase-1 按「已知文档类型」抽字段）
- 进 `99_无关文件` 或 coverage gap
- 或硬塞进「其他」，schema 对不上的段落被丢掉

整理的第一义务是**把纸面读全并归档**。类型识别是加分项，不能当滤网。

### 3.4 流程又臭又长，模型按最低成本执行

18 步 + 抗压缩长文，并没有让模型「老老实实读图」。它会保：

- 契约第一条：先跑确定性抽取
- 终态硬门：validator exit 0、PII clean、template_sha

丢掉的是贵而正确的那一步：每页完整视觉转写。于是出现「走了最低成本路径，最后因为校验循环并没有省钱，效果也没有变好」。

## 4. 目标形态

### 4.1 四条硬规则

1. **图的字符真值 = 多模态读图。** tesseract 若跑，只进 sidecar 附录，不能否决 vision，也不能单独把字段打成 `needs_human_review`。
2. **有文本层的 PDF 也要看图。** 电子字和像素一起喂给同一次多模态调用。电子字是对照，不是跳过读图的许可证。章、手写、红圈、勾选、被打乱的表，必须写入 Markdown。
3. **Markdown 是内容完整性的底；结构化是投影。** 投影失败，底还在。禁止「只出 JSON、不出全文」——未知类型对不上 schema 时内容会被丢掉，再也找不回来。
4. **14 桶是默认抽屉，不是白名单。** 规则外材料：全文 MD + 开放字段 + `15_其他资料/<类型名>/`。`gate_bucket_taxonomy` 不得因多了这个目录而 fail。

临床红线不动，见第 7 节。

### 4.2 被否决的替代方案

上一轮讨论里出现过「有文本层就只抽字、扫描件才走视觉」。**否决。**

理由：原生 PDF 同样有章、手写批注、圈选、页眉页脚图章、被 pdftotext 拆烂的多栏表。只抽字会系统性漏掉纸面上的信息。token 不能靠「少看图」省，要靠「每页只看一次、校验不要循环」。

### 4.3 单页输入：图和字一起进模型

```
          一页 PDF / 一张照片
                    │
         ┌──────────┴──────────┐
         ▼                     ▼
   渲染成图                 抽出该页文本层
   pdftoppm / 原图          pdftotext 该页
   （始终有）               （没有就空字符串）
         │                     │
         └──────────┬──────────┘
                    ▼
              一次 VLM 调用

     像素是要看的纸面。
     文本层是同一页嵌着的电子字，当对照，不当滤网。
     图上有、字里没有的（章、手写、红圈、勾选）必须写入 MD。
     字里有、图上糊的，写入并标明来自文本层。
     先写完全文，再抽字段。
     不要因为不像「病理报告」就省略段落。

                    │
                    ▼
┌───────────────────────────────────────────────┐
│  <file>.page-12.md                            │
│                                               │
│  ---                                          │
│  source: raw/...                              │
│  text_layer: present | absent                 │
│  doc_kind: 血常规 | 病理 | novel:肠道菌群     │
│  fields:                                      │
│    - {label, value, unit?, span}              │
│  uncertain: [ ... ]                           │
│  ---                                          │
│                                               │
│  # 全文                                       │
│  （版面转写；表格用 MD table；章/手写加标记）  │
└───────────────────────────────────────────────┘
```

扫描件不是「先 OCR」，是文本层为空、模型照样写全文。  
原生 PDF 不是「跳过读图」，是图 + 字同一响。

### 4.4 两层，不是 18 步

「先转 MD 再结构」和「第一步直接结构」都可以。采用折中：**按文件一次出齐，按患者再汇总。**

```
层 1  每页 / 每文件（贵，付视觉税，只付一次）
════════════════════════════════════════════

   并行切片，每页一次 VLM
        │
        ▼
   同一响强制两段输出
        ├─ 全文 Markdown     必须完整；禁止先填 schema 把其余丢掉
        └─ 页级开放字段      能抽就抽；抽不出不影响 MD 落盘

   未知类型：doc_kind = novel:<一句话命名>
             MD 照样完整
             fields 按纸面上能看见的键值原样列


层 2  跨文件（便宜，只读 Markdown，不再读图）
════════════════════════════════════════════

   所有 *.md
        │
        ▼
   患者级投影
        ├─ 已知槽位：labs.json / molecular.json / timeline / profile
        ├─ 开放槽位：extracted_fields.json（页级字段合并）
        ├─ 类型登记：source_inventory
        │            known | novel:<name> | unreadable
        └─ 归档位置：能对上 14 桶就进桶
                     对不上就进 15_其他资料/<doc_kind>/

   只有页级 MD 标了 uncertain 的字段
   才允许裁剪后再读一次图。禁止整档像素复读。
```

为什么必须留 Markdown 底：

```
只出 JSON、不出 MD
    → 未知报告对不上 schema，内容被丢掉
    → 结构抽错必须重新付视觉税
    → 跨页时间线各说各的

先有完整 MD
    → 未知报告至少全文在
    → 结构可重跑，不读图
    → 层 2 能看见全部材料再合并
```

### 4.5 开放世界怎么落库

```
现在（关闭）
  材料 → 这是 19 种 checklist 里的哪一项？
           是 → 填 schema
           否 → missing_items / 99_无关文件
                内容可能从未完整转写

重构（开放）
  材料 → 先当「一张纸」写完 MD
           能认成已知类型 → 填已知 JSON + 进对应桶
           认成新类型     → MD 全文 + 开放字段
                             进 15_其他资料/<类型>/
                             inventory 记 novel
           看不清         → MD 里写 unreadable 段落
                             原件仍在 raw/，不丢文件
```

「整理完成」的判据改为：

> 每份输入都有：`raw/` 原件 + 全文 Markdown + `source_inventory` 一行。

不再是「6 个 schema 都填满」。已知槽位尽量填；填不满不阻塞归档。

未知类型落盘示例：

```
patients/PT-…/
  raw/…/肠道菌群检测_2026-08.pdf
  15_其他资料/肠道菌群检测/
    2026-08-03_肠道菌群检测_某检验所.md
  extracted_fields.json
  source_inventory.json          kind: novel:肠道菌群检测
  labs.json                      只含对得上的化验
                                 对不上的留在 MD 和开放表
```

`99_无关文件` 只留给真正非医疗材料（风景照、聊天截图），且仍须先有全文/说明 MD，删除仍要逐项确认。不得把「我们没见过的检验单」当无关文件。

### 4.6 整条流程对照

```
现在                                      重构
──────────────────────────────────        ──────────────────────────────────
确定性 OCR / 文本层 = 字符真值            多模态（图+字）写出的 MD = 字符真值
LLM 只能 proposed，不能覆盖               tesseract 最多进附录，不能否决
14 桶 + 6 schema 是滤网                   14 桶是默认抽屉；MD 保完整
规则外 → 隔离 / 缺失                      规则外 → novel 全文落库
Phase-2.5 整档再读像素                    只复读 uncertain 字段
PII agent 循环 5 轮                       脚本一轮；语义扫描至多一次
18 步编排                                 4 段：适配 → 转写 → 投影 → 门+渲染
增量 7 行化验单走完整 4 worker            文本页走层 1（几乎无图）→ append → 脚本门
```

四段编排：

```
0. 适配（无 LLM）
   解压 · HEIC 转码 · PDF 按页渲染
   每页打包 {image, text_layer}

1. 转写（VLM，并行）          ← 唯一的视觉税
   每页 → 完整 MD + 开放字段
   不问「这是不是我们的类型」

2. 投影（LLM，只读 MD）
   已知 JSON + 开放字段表 + 14 桶或 15_其他
   跨页时间线 / 矛盾并列（不选赢家）

3. 门 + 渲染（脚本）
   形状 / PII 形状 / 模板 HTML
   一轮，不循环
```

## 5. 速度、效果、token 如何同时变好

视觉税每页只付一次。省的不是「少看图」，是「不要把同一页看 8 遍，再审 5 轮」。

同一页扫描（PT-84 的 s4 类钼靶截图）：

```
现在
  匀光 → tesseract → 0 字节 → 全页 vision → 修订
  → 再 OCR 比对 → human_review → Phase-2.5 再读 → PII 再扫
  约 8 次读图/页，字还是进不了 settled fact

重构
  图 +（空或有）文本层 → 1 次全页 VLM → 完整 MD + 开放字段
  只有 Hb / 剂量 / 变异等标了 uncertain 的，才裁剪二读
  约 1 次全页 + 0～4 次裁剪
```

同一份整理的 token 结构（PT-84，量级估计，不是承诺小数）：

```
现在 192M
  读图 + OCR 打架     99M    每页多读、修订留痕
  门禁循环            48M    2.5 整档 + PII×5
  综合 / 编排 / 摘要  45M

重构 约 70–90M
  每页一次 VLM        主成本，该花（含原生 PDF 的图+字）
  层 2 只读 MD        不再读图
  脚本门              几乎 0
  不确定字段裁剪      偶发
```

墙钟目标（同一量级材料、并行切片保留）：完整整理从 1.5–4 小时压到 **1 小时以内**；7 行纯文本增量从 30 分钟压到 **2 分钟以内**。

效果为什么会比现在好：

| 场景 | 现在 | 重构后 |
|---|---|---|
| 难页（摩尔纹、屏幕翻拍、织物纹理） | vision 被 tesseract 否决，flag 一堆 | MD 里就是 vision 读到的字 |
| 原生 PDF 上的章 / 手写 / 圈选 | 只抽文本会漏 | 图+字同读，写入 MD |
| 未知报告类型 | 隔离或抽残 | 全文在，开放字段在 |
| 结构抽错 | 要重付视觉税 | 重跑层 2 |
| 就诊准备包 | OCR 打架当「问医生」 | 没有这场架；只有真看不清的字段 |

## 6. 不变的红线

这些不在本次谈判范围，重构后仍然成立：

- 不推断分期、ECOG、疗效、进展、治疗线、预后
- `source_reported` / `patient_reported` / `caregiver_reported` / `system_normalized` 互不覆盖
- 冲突保持 `disputed`，患者确认不能指定临床赢家
- 原件进入受控 `raw/`，不去标识原件、不静默删除
- 患者向 HTML 必须走模板，带 `template_sha256`，禁止手写 HTML
- PII：派生面要遮蔽；遮蔽不得改药名、剂量、变异、单位
- 导出仍要授权、目的限制、白名单，不含 `raw/`

读图是感知，不是判决。把感知交给弱 OCR，再让强模型去审计弱感知，既慢又贵，识别还上不去。本次把感知层改回来，判决层不动。

## 8. 成功标准（review 通过后用来验收，不是本次改代码）

对照材料必须包含真实难页，禁止只用合成 PDF。建议仍用 PT-84 的扫描合订本（s2–s4）+ 至少一份规则外材料（例如菌群 / 骨密度 / 外文报告）。

| 指标 | 现在（PT-84 整理） | 重构后目标 |
|---|---|---|
| 整理总 token | 192M | 明显下降（量级 70–90M；原生 PDF 仍付视觉税，不靠少看图取巧） |
| 模型步 | 1220 | 量级腰斩 |
| 墙钟 | 1.5–4 h | < 1 h（并行切片保留） |
| 增量 7 行化验单 | 30 min / 7.8M / 4 worker | < 2 min，不派忠实度+PII 双 worker |
| 难页进档案的字段 | 大量 `needs_human_review`，值用不上 | vision 写入 MD 的字可进 settled fact；仅两次 vision 仍不一致才 flag |
| 就诊准备包「请医生确认」 | 9 条里 7 条是 OCR 小数点 | 0 条 OCR 打架；只留真看不清或跨源矛盾 |
| 规则外材料 | 易进无关文件 / 抽残 | 全文 MD + novel 目录 + inventory 一行 |
| validator | 形状合法 ≠ 字读对 | 完成判据改为 raw + MD + inventory；形状门仍跑，但不替代转写质量 |

对照跑只看上面这些数。`validate_structured_outputs.py` 全绿只证明形状合法，不证明字读对了。

## 10. 请 reviewer 拍板的问题

1. **第二读是否允许「换一个 vision 模型」？** 草案：高风险 + uncertain 才裁剪再读；默认同一模型即可，不强制双模型（成本与调度复杂度）。
2. **tesseract 还要不要跑？** 草案：默认不跑；host 若已安装，可写入附录供审计，但**永远不能否决 MD 正文**。
3. **`15_其他资料` 的命名。** 是否接受这个桶号，还是用 `14_患者自管补充` 下的 `未分类/`。倾向独立桶，避免和患者自述混在一起。
4. **层 1 是否强制「同一响既出 MD 又出字段」？** 草案：是，但 MD 完整优先于字段完整。若上下文爆掉，允许先只出 MD、层 2 再抽字段。
5. **PII 语义扫描是否完全降为可选？** 草案：脚本形状门必跑；语义扫描在导出前必跑，在普通整理里至多一轮，不再是完成门的循环条件。
6. **SMTB 是否跟这次一起动？** 草案：不动。SMTB 审查循环是另一笔 3.2 亿 token，另开文档。
