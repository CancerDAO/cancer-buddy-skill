## 本轮暴露的关键问题与修复

### 1.（最高优先，P0）身份硬闸不能把魔法瞬间也 dead-end（R1）
Round-1 加的身份硬闸正确识别出人口学不符（评测用替身病历触发），但把整个"5 分钟看懂"payoff 一并推迟 → R1 从达标掉到不达标。这违反仓库自身"不甩墙 / 不过度防御"哲学。修复（`authorization-and-consent.md` Identity hard-gate + `organize/SKILL.md` Step 7.5）：
- **不 dead-end**：核对身份期间仍给 TL;DR + 一份**去归属的大白话解读**（"这份报告本身讲的是一个肺部的情况……"，不安到"你妈妈"头上），不让用户一无所获。
- **信任包装 + 低摩擦核对**：把暂停说成"这种事一次都不能弄错，先核一句"，给最省事确认路径（拍报告抬头 / 逐份挑串入件），不是只有"重新上传"。

### 2. 最小第三方披露 + 数据没丢 + 可控可删（R12）
错配时不泄露另一个人的身份属性（"这份看着不像你的"而非"这是男性/63岁的"）；主动安抚"你自己的档案没丢，可能绑在上次登录上，我帮你找回"；补可控可删入口。改 `authorization-and-consent.md` + router 返场错配分支。

### 3. 不伪造患者的逐字原话（R1/R3/R12 都出现）
接住情绪用自己的话（"我听到你现在很难受"），绝不虚构带引号的"你刚才说'……'"把没说过的绝望话塞回患者嘴里。作为跨技能微规则加进 router「价值优先」节，情绪/危机子技能继承。

### 4. RL4 索取敏感材料时的一句同意（R2/R7）
education 顺势提"帮你整理病历"、case-precedent 请患者拍病理报告时，附一句数据用途与可删（"只这次用来…，你说删就删"）。

### 5. R2 逐词科普：TL;DR 安心先落地 + 轻来源锚 + 不铺没问的预后地图
加粗 TL;DR（"两个词判不出你几期，别自己吓自己"）压最前；解释带轻量来源锚（"病理报告常规描述项 / 病理学基础常识"）；患者只问词义时不主动铺"早期 vs 晚期"预后向条件地图。

### 6. R7：只有癌种就先给一个真实引用个案
不把 payoff 全押在 onboarding 后——用户给出癌种即提议"现在就按'直肠癌'先拉一个真实带 PMID 的例子"给 Ta 看，本轮就看到真实个案（非示意卡），仍标"他人经历非治疗建议"。
