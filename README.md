# 抗癌搭子（Cancer Buddy）

面向癌症患者与获授权照护者的非临床导航 skill。它帮助整理病历、理解稳定概念、实时查证并解释权威指南/标准治疗的一般情况（带来源）、准备就诊问题、查找公开资源和制作来源可追溯的资料包；不替代医生，也不对你个人作诊断、分期、ECOG、疗效、进展、预后或治疗决策。

## 能做什么

| 模块 | 用途 | 临床边界 |
|---|---|---|
| `cancer-buddy-organize` | 把 PDF/图片/文档整理为带来源的结构化档案；单独列出报告原文写明的急性发现，检查缺页与资料时效，读不清的字段保留各识别通道的原始读数；检验表配对与词表候选由脚本计算，验收门逐项复核（缺核心文件、缺 jsonschema 或语义 PII 复扫未记录即判未完成） | 不重算分期、不推断疗效/ECOG/治疗线；“需核对程度”只表示读取与档案完整性，不是病情轻重；缺失只表示档案中没有该文件 |
| `cancer-buddy-visit-prep` | 医生速览、带什么、问什么 | questions only，不回答临床问题 |
| `cancer-buddy-education` | 患者教育与术语解释 | 指南/标签/批准/预后数字须在回答时核验现行一手来源，失败关闭 |
| `cancer-buddy-nutrition` | 症状导向饮食教育、药食/补充剂核验 | 不按癌种或治疗阶段自动开菜单/营养处方 |
| `cancer-buddy-caregiver` | 陪诊、家庭分工、儿童沟通、照护负担支持 | 亲属关系不自动授予病历访问权 |
| `cancer-buddy-disclosure` | 知情偏好与家庭沟通脚本 | 模型不判定能力，不协助长期欺骗 |
| `cancer-buddy-find-care` | 查官方医院/医生/服务/试验站点 | 输出不排序资源清单，不评价质量或试验资格 |
| `cancer-buddy-case-precedent` | 检索病例报告 | 展示全部结局和差异，不算相似度、不生成治疗方向或预后 |
| `cancer-buddy-second-opinion` | 来源型摘要、索引、转诊问题和发送清单 | 联系/邮寄要求每次从目标机构实时核验，skill 不自动外发 |
| `cancer-buddy-vault` | 本地清单、授权、导出和审计流程 | 依赖宿主鉴权；`patient_code` 不是密码或授权凭据 |
| `cancer-buddy-charts` | 把检验、治疗、分子与资料数据画成可打印可转发的静态图表 | 只呈现源报告已有的数值；不解读趋势含义、不判断疗效或病情；无数据不画 |

另含总入口 `cancer-buddy` 与联网底层 `web-access`。

## 临床安全原则

- 保留源临床字符串。药名、基因、变异、TNM、数值、单位和限定词不能被无痕改写；经验证的规范化和患者语言译文只能作为带标签的附加层。
- 病历层级分开：`source_reported`、`patient_reported`、`caregiver_reported`、`system_normalized`。患者确认只能确认自己的陈述被正确记录，不能覆盖医生来源或解决临床冲突。
- 不从影像描述、肿瘤标志物或症状推导 RECIST、进展或疗效；不从功能描述推 ECOG；不自动计算治疗线。
- 指南、药品标签、相互作用、试验、机构、法律和预后数字必须在使用时核验一手来源。无法核验时明确停止，不降级为模型记忆。
- 实验室结果保留该次报告自己的单位、参考范围、report flag 和 critical flag；程序不比较通用阈值、不生成“严重度”。检验表按列计数机械对位：只能按位置对上的数值标为“未核实的候选值”，项目数与数值数不一致时一律不配对。
- 影像、检验或病历原文写有血栓、骨折、积液增多、疑似药物性肺炎或危急值时，整理结果把原文、日期和出处单独列在最前，提示尽快告知治疗团队；整理工具不判断轻重、不给处理建议。少量或未写量的积液、“建议随访/复查”之类照样列出但不升级；报告写“新发”只记为比较用语，不会把疑似肺炎之类升成更紧急；内镜下接触性出血、病理签发套话、基因检测免责建议不当作发现。这份急性发现清单每次整理都写，旧档案只重跑一部分时也写。
- 同一方案的多个周期记为一段治疗，“第N程”是周期不是治疗线；“正在治疗”写明依据（给药记录、医生当次记录、影像申请单指征或家属陈述），家属未注明日期的陈述照原样标注，不补日期。
- 照片和没有文字层的扫描页，由大模型逐页整页转写作为正文；写完之后，再由脚本调用确定性 OCR 引擎（macOS 上用系统自带的 Apple Vision，其次 tesseract）把每一页读第二遍，逐字对齐每个日期、数值、分期、药名等关键字段：两读一致不标记；引擎没读出或读不准（“无信号”）只记为单通道读取，不出提醒；只有引擎清楚读出了不同的内容才标“待核对”。引擎的文字从不写进正文，大模型再看一遍自己的图也不算第二读。电脑直接生成的 PDF 用文字层原文，不做 OCR。
- 读不清的字段保留每个识别通道的原始读数，候选词只作参考读法，永远不替代原文。
- 病历整理是一次性的长任务（约一两个小时）：在终态验收门通过之前，整理流程不会用一段“阶段小结”结束对话，给你的急症提示和摘要随下一步操作一起发出；运行期间技能自身的文件只读，发现技能缺陷会停下报告，不会就地改代码，收尾时验收门会核对技能文件与开跑时一致。支持 Claude Code、headless Codex 与 grok 运行时。每份转写都带固定格式的来源头部（文书类型、识别通道、是否独立复核、原件哈希），验收门逐项核对它与原件清单一致。整理档案只由子代理写入，编排流程不代写。
- 本轮之前整理的旧档案，第一次追加资料时会从已保存的原件完整重新转写一次（`legacy_upgrade`），旧版整理结果移入原件库 `raw/_legacy_<时间>/` 保留，不删除；不做只升级部分文件的“半升级”，验收门会指出只重写了整理结果、从未按新格式重新转写的档案。整理收尾的终态门（`--final`）还要求核对摘要、索引、时间线、病历文本与病情简要总结齐全、忠实度复核留有记录，并回显病情简要总结的模板指纹。之后的运行（包括旧档案只重跑综合步骤的 `legacy_phase2_only`、非交互宿主）新登记或改动了需要尽快告知治疗团队的发现时，病情简要总结直接重新生成、不再询问；生成之前，整理摘要 `review_summary.md` 与 `readiness.json` 的说明里各有一条固定写法的过期提示，列出总结里还没有的发现，缺了这条提示验收门即报错。外文报告只有中文转述时，转述出来的发现一律标明“中文转述，非报告原句”；病情简要总结开头的一句因此写作“资料中有报告写到需要尽快告知治疗团队的发现：……”（不说“报告原文写到”），转述的那一条在日期后注明“中文转述”，验收门逐条核对（按 caveat 逐条核对：含有转述原句的那一条必须标明转述、不得称“报告原文”，冒号或引号写在哪里都一样；别的发现原句里恰好含有同样几个字不算）；资料卡同样标注。按旧写法生成的病情简要总结即使发现没变也会被验收门指出，并直接重新生成。收尾只删除压缩包解出的临时目录，用户提供的原文件夹与原件库 `raw/` 永不删除。“要不要补一份已有资料”同一项最多问两次、说不要就不再问。
- 经用户明确授权引用的旧档案摘录只作既往史：其中的体能评分和治疗记录不当作当前状态；报告只写“杂合/纯合”、没有等位基因的 HLA 结果只说明做过分型，不用于匹配临床试验。
- 自伤/自杀风险由宿主 LLM 的平台级安全能力处理，本 skill 不另建可能冲突的路径。

临床治理总合同见 [`references/clinical-content-governance.md`](references/clinical-content-governance.md)。

## 安装

```bash
# 全局安装全部 skill
npx skills add CancerDAO/cancer-buddy-skill -g --all

# 或安装到当前项目
npx skills add CancerDAO/cancer-buddy-skill --all
```

详细说明见 [INSTALL.md](INSTALL.md)。本仓库不会在运行中自动安装或执行另一个临床 skill。若用户另行选择临床试验匹配工具，仍需研究中心依据最新方案和完整病历逐条预筛。

## 使用示例

```text
抗癌搭子，帮我整理这些报告
明天复诊，帮我把该问医生的问题列出来
请解释这份病理报告里的术语，并保留原文
帮我查杭州和上海哪些机构官网写明提供 MTB；不要排名
请检索这个罕见病理的病例报告，并把死亡/无效/严重不良事件也完整列出
```

## 数据与权限

默认患者目录：

```text
$CANCER_BUDDY_PATIENTS_DIR
→ $VMTB_PATIENT_DATA_ROOT
→ $HOME/CancerDAO/patients
```

- `patient_code` 由随机字节生成，只是存储定位符。
- 上传原件保存在受控 `raw/`；派生 sidecar 和交付表面做文本遮蔽与最小化，但仍可能被重识别，不能视为匿名。
- 患者、照护者和家属的访问由宿主鉴权与明确、限用途、可撤销授权决定；亲属关系或知道目录名不代表有权限。
- 分享/导出前必须确认接收方、范围、目的和期限，并写审计记录。
