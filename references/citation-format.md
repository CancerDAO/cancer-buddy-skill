# 引用格式（全局共享合同）

本文件是 cancer-buddy 全部 skill 与 sub-skill 的**统一引用规范**。任何面向患者输出的
子技能都必须遵守，不得自行发明标签类型或编号规则。

引用**什么时候必须出现**由 `clinical-content-governance.md` §2（answer-time 核验）与
`safety-guardrails.md` §Live external lookup 决定；本文件只规定**出现时长什么样**。

## 1. 四类来源标签

| 标签 | 用于 | 脚注必须显示 |
|---|---|---|
| `〔档案〕` | 患者自己的档案：医院出具的报告、出院小结、医嘱，以及主诊团队对本人的书面交代 | 文档名 + 日期 + 档案内锚点 |
| `〔资料库〕` | 参考文献库命中项：产品自带的结构化清单，以及用户合法持有、已在 `index.json` 登记且版本未过期的资料 | 出版者/发布方、标题、版本或收录批次、数据截止日、页码或条目号。**不显示主机绝对路径** |
| `〔联网〕` | answer-time 实时取回的官方一手来源 | 直接 URL + 访问日期 |
| `〔文献〕` | 论文、系统综述、病例报告 | 标题 + PMID/DOI |

**只有这四类。** 不新增、不细分、不在标签里写内部分级术语（如信任层级、`user_supplied`
之类）——那些是产品内部机制，不是患者需要读的词。

## 2. 编号与关联

- 正文内联角标从 `1` 连续递增、无缺口，与文末清单一一对应
- 一条脚注只为一条原子主张背书，不得一号多用
- 引用必须出现在**患者可见输出**里，而不只是内部落盘文件
- 即使是简短对话式答复，只要含版本敏感断言，就必须在该答复内出示编号来源，
  不得以「只是聊天短答」省略

## 3. 出处写进正文，不靠标签承载

标签只表明来源**类别**，具体出处用自然语言写在正文里：

> 你出院小结上写着「体温≥38.0℃ 立即联系管床医生 13x-xxxx-xxxx」<sup>[1]</sup>，
> 你现在 38.4℃ 已经超过这条线了——现在就打这个电话。

患者读到「你出院小结上写着」就知道来源了。标签是给引用体系用的，不是让患者去解码的。

## 4. 时效敏感断言必须并列实时核验

获批状态、医保报销、试验在招、指南版本、中心名单这五类，**即使 `〔档案〕` 或
`〔资料库〕` 已命中，也要并列给出 `〔联网〕` 核验结果**。本地命中提供骨架与线索，
实时来源确认当前状态。核验不可达时按 `safety-guardrails.md` fail-closed 处理，
如实标注未核实，不以本地命中冒充当前。

## 5. 内部信任分级不外显

skill 内部按来源位置判定该条信息能否作为依据（产品自带清单 vs 用户投放资料），
这个判定**只影响 skill 怎么用它**，不改变患者看到的标签，也不出现在患者可见文本里。
