# Patient Profile Schema

This file defines the filesystem contract shared between `cancer-buddy-skill` and `vmtb-skill`. Both plugins read and write under the same `patients/<patient_id>/` tree. Every sub-skill that writes `profile.json`, `timeline.md`, or `readiness.json` must honor the fields here.

## Directory layout

```
patients/<patient_id>/
├── INDEX.md                  # overview; patient_id declared on first line
├── profile.json              # structured profile (write: organize only)
├── timeline.md               # human-readable treatment timeline
├── readiness.json            # MTB readiness score
├── case_text.md              # consolidated narrative
├── 01_当前状态/ ... 11_诊断证明/
├── ocr/                      # OCR sidecars
└── reports/
    ├── mtb-lite/             # cancer-buddy-mtb-lite
    ├── mtb-full/             # vmtb-skill cancerdao-vmtb
    ├── explore/
    ├── trials/
    ├── access/
    ├── manage/
    └── education/
```

## patient_id

Format: `<姓名首字母拼音>_<诊断年月>`, e.g. `WZM_202312`.
- Generated by organize on first run, persisted as the first line of `INDEX.md` (format: `# patient_id: WZM_202312`).
- Must be unique within the `patients/` root. On collision, append `_<n>` (WZM_202312_2).

Required at minimum for downstream skills to function: `patient_id`, `diagnosis.primary_site`, `diagnosis.histology`, `diagnosis.stage`. If these are missing, downstream skills must prompt the user to re-run organize.

## readiness.json

```json
{
  "schema_version": "1.0.0",
  "grade": "A|B|C|D|F",
  "scored_at": "2026-04-23T10:00:00Z",
  "domains": {
    "diagnosis": {"score": 0.95, "missing": []},
    "staging": {"score": 0.90, "missing": []},
    "pathology": {"score": 1.0, "missing": []},
    "molecular": {"score": 0.60, "missing": ["TMB"]},
    "treatment_history": {"score": 1.0, "missing": []},
    "imaging": {"score": 0.80, "missing": []},
    "labs": {"score": 0.90, "missing": []},
    "comorbidities": {"score": 1.0, "missing": []}
  }
}
```

Grade mapping: A ≥ 0.90, B ≥ 0.75, C ≥ 0.60, D ≥ 0.40, F < 0.40.

Every sub-skill reads `readiness.json` at entry:
- If file missing → prompt user to run `cancer-buddy-organize`.
- If grade < C → prompt for additional records or trigger organize deep-dive.
- If grade ≥ C → proceed.

## Field-change discipline

Only `cancer-buddy-organize` (and `cancerdao-vmtb`'s `vmtb-organizer` subagent) may write `profile.json`, `timeline.md`, `readiness.json`. Any other sub-skill that wants to reflect new information (e.g. a new imaging study) must trigger an organize re-run, not mutate in place.

## Defensive reads

All consumers must tolerate missing optional fields — surface a prompt, do not crash. Missing required fields trigger the re-organize suggestion above.

## Version pin

Declared tested against `vmtb-skill` ≥ 4.0.0-beta.6. Breaking schema changes bump this file's `schema_version` first, vmtb-skill follows.
