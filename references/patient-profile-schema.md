This file defines the filesystem contract shared between `cancer-buddy-skill` and `vmtb-skill`. Both plugins read and write under the same `patients/<patient_code>/` tree. Every sub-skill that writes `profile.json`, `timeline.md`, or `readiness.json` must honor the fields here.

The canonical writer is the `cb-organizer` subagent (mirrored from `vmtb-organizer`); all other sub-skills are read-only consumers, with the named exceptions documented under [Field-change discipline](#field-change-discipline).

## Canonical shape

`profile.json` uses a **nested** shape, enforced by `scripts/validate-profile-schema.sh` and `tests/unit/validate-profile-schema.test.sh`. Those two artifacts are the source of truth; this document follows them. The validator ignores unknown top-level keys, so the optional blocks below are safe to add even though the validator does not assert them.

## Directory layout

```
patients/<patient_code>/
├── INDEX.md                  # overview; patient_code declared on first line
├── profile.json              # structured profile (write: organize / vmtb only, see exceptions)
├── timeline.md               # human-readable treatment timeline
├── readiness.json            # MTB readiness score
├── case_text.md              # consolidated narrative
├── role.json                 # per-session role state (see role.json section)
├── 01_当前状态/ 02_基本信息/ 03_病理报告/ 04_影像学/ 05_检验/
├── 06_治疗记录/ 07_NGS 分子检测/ 08_手术-内镜/ 09_会诊-转诊/
├── 10_原始文件/ 11_诊断证明/
├── ocr/                      # OCR sidecars (per-file text extracts)
└── reports/
    ├── mtb-lite/             # cancer-buddy-mtb-lite (pro-skill)
    ├── mtb-full/             # vmtb-skill cancerdao-vmtb
    ├── explore/              # pro-skill
    ├── trials/
    ├── access/
    ├── manage/               # pro-skill
    ├── comfort/              # pro-skill (acp_status, symptom-log)
    └── education/
```

## patient_code

Format: `PT-<hex>`, e.g. `PT-17CE02BC33`.
- Generated by organize on first run (hash of input basename + mtime), persisted as the first line of `INDEX.md` (format: `# patient_code: PT-17CE02BC33`).
- Callers may supply a `patient_code` argument to override. Must be unique within the `patients/` root; on collision the organizer appends `_<n>`.

## profile.json

Shape written by `cb-organizer` (shared with `vmtb-organizer`):

```json
{
  "schema_version": "1.0.0",
  "patient_code": "PT-17CE02BC33",
  "diagnosis": {
    "primary_site": "非小细胞肺癌",
    "histology": "腺癌",
    "stage": "IIIA (cT3N2M0)"
  },
  "basics": {
    "ecog": 1,
    "sex": "F",
    "age": 65
  },
  "treatment_history": [
    {"line": 1, "start": "2024-01-15", "regimen": "osimertinib 80mg qd"}
  ],
  "surveillance_schedule_anchor": "2025-08-30",
  "disclosure_state": "full",
  "acp_status": "none",

  "geo": {
    "current_city": "上海",
    "willing_to_travel": true,
    "willing_radius_km": 800
  },
  "economic": {
    "budget_band": "mid"
  },
  "insurance": {
    "type": "城镇职工医保",
    "enrolled_city": "上海"
  },
  "molecular": {
    "drivers_known": true,
    "drivers": [
      {"gene": "EGFR", "variant": "L858R", "vaf": 0.32, "source": "07_NGS 分子检测/ngs-20240115.pdf"}
    ]
  },

  "caregivers": [
    {
      "relation": "spouse|parent|child|sibling|friend",
      "name": "张 *",
      "is_primary": true,
      "contact_preference": "wechat|phone|email|none",
      "lives_with_patient": true
    }
  ],
  "disclosure_history": [
    {"state": "suppressed", "set_at": "2024-03-10T09:00:00Z", "set_by_role": "caregiver"},
    {"state": "partial",    "set_at": "2024-05-20T11:00:00Z", "set_by_role": "caregiver"},
    {"state": "full",       "set_at": "2025-01-15T14:30:00Z", "set_by_role": "patient"}
  ]

```

Fields are left `null` or omitted when truly unknown — the organizer never fabricates.

### Required fields

These are enforced by the validator; a profile missing any of them fails schema validation and downstream skills must prompt the user to re-run organize.

| Field | Type | Notes |
|---|---|---|
| `schema_version` | string | Exactly `"1.0.0"`. |
| `patient_code` | string | `PT-<hex>`; matches the directory name. |
| `diagnosis` | object | Must contain `primary_site`, `histology`, `stage` (all required sub-keys). |

### Optional blocks

All optional. The validator type-checks the ones it knows (`basics.ecog`, `basics.sex`, `disclosure_state`, `acp_status`, `surveillance_schedule_anchor`, `treatment_history[]`) and **ignores** unknown keys — so `geo` / `economic` / `insurance` / `molecular` are safe to add and are read by find-care and other skills. They must be defined here because downstream skills depend on them.

| Field | Type / enum | Notes |
|---|---|---|
| `basics.ecog` | int 0–4 | Performance status. |
| `basics.sex` | `"M"` \| `"F"` | |
| `basics.age` | int | |
| `treatment_history[]` | array of `{line:int, start:"YYYY-MM-DD", ...}` | Validator enforces `line` non-decreasing and `start` chronological. Additional keys (e.g. `regimen`) allowed. |
| `surveillance_schedule_anchor` | `"YYYY-MM-DD"` | Starts the survivorship clock. Written by organize on transition to maintenance/post-treatment, or explicitly by patient/caregiver. |
| `disclosure_state` | string enum: `"full"` \| `"partial"` \| `"suppressed"` \| `null` | See dedicated section below. NOT an object — never a `.suppressed` sub-field. |
| `acp_status` | `"none"` \| `"discussed"` \| `"documented"` \| `"legally_filed"` \| `null` | Advance care planning progress. Written by `cancer-buddy-comfort` (pro-skill). |
| `geo` | `{current_city:string, willing_to_travel:bool, willing_radius_km:int}` | Read by find-care for hospital/center matching. |
| `economic` | `{budget_band:"low" \| "mid" \| "high" \| null}` | Affordability band for option filtering. |
| `insurance` | `{type:string, enrolled_city:string}` | 医保参保地. **Replaces the old, wrong `medicare_city` naming** — `insurance.enrolled_city` is the canonical key. |
| `molecular` | `{drivers_known:bool, drivers:[{gene,variant,vaf,source}]}` | Each driver carries its `source` path back to the report it came from. |

### caregivers[]

`caregivers[]` (optional array) records who the operator is when the patient is being helped by family. It is populated by **`cancer-buddy-caregiver`** at the role-caregiver first interaction, and read by downstream sub-skills to know who they are addressing.

This is an **explicit, named exception** to the [Field-change discipline](#field-change-discipline) rule below: `cancer-buddy-caregiver` is permitted to write `profile.caregivers[]` directly, in addition to `cancer-buddy-organize` and `cancerdao-vmtb`. No other field of `profile.json` may be touched by `cancer-buddy-caregiver`; it owns `caregivers[]` only.

### disclosure_state and disclosure_history

- `disclosure_state` (optional, default `null` interpreted as `"full"`): whether the diagnosis is known to the patient. It is a **string enum** (`"full"` | `"partial"` | `"suppressed"` | `null`), never an object. When `"suppressed"`, downstream skills in patient role apply softened/refuse behavior per `disclosure-behavior.md`.
- `disclosure_history` (optional): append-only log of state transitions, each `{state, set_at, set_by_role}`, recording who set each state and when.

## readiness.json

**⚠️ 内部字段声明：`score`、`grade` 仅供 `preflight.md` 路由判断使用，禁止出现在任何用户侧文档（review_summary.md、case_summary_brief.md、case_summary_detailed.md、profile-card）中。用户侧只展示 `tier1_gaps[]` 和 `tier2_gaps[]` 翻译成的行动指引。**

Schema version 升至 `"2"`（新增 tier1/tier2 字段，向后兼容：旧消费者读到 schema_version:"1" 时仍可读 blocking_gaps）。

```json
{
  "schema_version": "2",
  "score": 72,
  "grade": "B",
  "cancer_type_used_for_tier2": "<癌种，如 肺腺癌 | 乳腺癌 | 结直肠癌 | null（未确认时）>",
  "tier1_gaps": [
    {"item": "<缺失的 Tier1 项，如 病理报告>", "reason": "<说明缺此项对分析的影响>"}
  ],
  "tier2_gaps": [
    {"item": "<该癌种 Tier2 清单中缺失的项>", "priority": "high|medium", "reason": "<临床意义说明>"}
  ],
  "tier2_covered": [
    {"item": "<已覆盖的 Tier2 项>", "evidence": "ocr/<sidecar文件名>.md"}
  ],
  "blocking_gaps": [{"domain": "<domain名>", "reason": "<缺失原因>"}],
  "warnings": [],
  "review_flags": [
    {
      "id": "RF-001",
      "severity": "red",
      "category": "format_violation",
      "field_path": "diagnosis.stage",
      "current_value": "rpT4aN2aM1 IV期",
      "issue": "AJCC 8th 标准前缀只有 c/p/yp/r/a, 'rp' 不在其中",
      "source_evidence": ["10_原始文件/出院诊断证明_2024-07-05.jpg"],
      "suggested_value": "pT4aN2aM1 IV期",
      "suggested_action": "改写为 pT4aN2aM1; 在 data_sources 注明源文件统一写作 rpT4aN2aM1 (推断为医院习惯)",
      "user_confirmed": false,
      "rationale_for_suggestion": "首诊→手术间隔≤30天,病程明确写'辅助化疗'(非新辅助),故术中标本应为treatment-naive → p前缀"
    }
  ]
}
```

- `schema_version` is `"2"` for new profiles; `"1"` for legacy (no tier fields). Downstream consumers check `schema_version` before reading tier fields.
- Grade mapping (internal only, not for display): A ≥ 90, B ≥ 75, C ≥ 60, D ≥ 40, F < 40.
- Score formula: `round(tier1_score × 0.6 + tier2_score × 0.4) × 100` where each tier_score = filled_items / expected_items.
- Downstream routing uses `tier1_gaps[]` (non-empty = prompt user to add records, but do not block report generation).

### review_flags[] (required, may be empty array)

Items where the organizer **successfully extracted a value but the value or its writing is suspicious**. Distinct from `blocking_gaps` (which is about coverage) — `review_flags` is about **trustworthiness of what was extracted**.

Detection categories (organizer must check all five before returning):

| category | trigger |
|---|---|
| `format_violation` | Field violates a known standard (TNM prefix not in AJCC c/p/yp/r/a; mixed unit/case in same record; non-canonical drug name). |
| `cross_doc_contradiction` | Same conceptual field has conflicting values across docs (cycle 6 vs cycle 1 of new regimen; weight 65kg vs 70kg same week). |
| `clinical_logic_anomaly` | Term used in semantically wrong context (adjuvant chemo + RECIST PR; "新辅助" in upfront-resection patient; ECOG 0 + KPS 50). |
| `unverified_critical_field` | Field is critical for downstream (molecular driver / stage / line of therapy) but only sourced from progress narrative, no primary report. |
| `value_trend_anomaly` | Lab/biomarker shows non-physiologic jump or unit-suspect change (TSH 6.49 → 0.80 in 8 weeks unexplained; CEA dropping 100× in one cycle). |

Each entry MUST contain: `id` (`RF-NNN`), `severity` ∈ {red, yellow, green}, `category` (from table), `field_path` (dot path into profile.json), `current_value`, `issue` (≤80 chars Chinese summary), `source_evidence[]` (paths to OCR sidecars or 10_原始文件 entries that support `current_value`), `suggested_action`, `user_confirmed: false` on first write.

May contain: `suggested_value` (concrete proposal), `rationale_for_suggestion`.

**Severity rules:**
- 🔴 `red` — affects downstream eligibility / dosing / line counting (wrong stage prefix, unverified molecular driver, line-count ambiguity)
- 🟡 `yellow` — should be reviewed but won't break downstream (cycle numbering, term-misuse, value-trend without explanation)
- 🟢 `green` — informational hint (substage precision optional, supporting data desirable)

**Empty-array semantics:** organizer found no suspicious extracted values. Empty ≠ skipped — organizer must always run the five checks and surface intermediate findings even when none reach severity threshold.

**Companion artifact `review_flags.md`** — auto-generated human-readable rendering of the array, written to `patients/<patient_code>/review_flags.md` for direct user reading. Source of truth is the JSON; the .md is regenerated on every organize.

Every sub-skill reads `readiness.json` at entry:
- If file missing → prompt user to run `cancer-buddy-organize`.
- If grade < C → prompt for additional records or trigger organize deep-dive.
- If `review_flags[]` contains any unconfirmed `red` items → display them to the user and require confirm/override before producing recommendations. The user's resolution (`accept_suggestion` | `keep_original` | `custom_value` | `defer`) is logged back into `review_flags[i].user_confirmed = true` plus a `resolution` sub-object.
- If grade ≥ C and no unresolved red flags → proceed.

## role.json — single source of truth

Per-session role state. This is the **single, authoritative definition** of `role.json`; `roles.md` links here rather than re-listing it.

```json
{
  "schema_version": "1",
  "active_role": "patient|caregiver|family",
  "set_at": "2026-04-23T10:00:00Z",
  "history": [{"role": "patient", "set_at": "2026-04-20T09:00:00Z"}]
}
```

- `active_role` ∈ `"patient"` | `"caregiver"` | `"family"` (enforced by the validator).
- `history[]` is an append-only list of prior `{role, set_at}` transitions.

Written and read by the meta-skill. Every sub-skill reads `patients/<patient_code>/role.json` at entry. If missing → route back to meta-skill for role resolution. The per-role tone rules and per-skill role matrix live in `roles.md`.

## Field-change discipline

Only `cancer-buddy-organize` (via the `cb-organizer` subagent) and `cancerdao-vmtb` (via its `vmtb-organizer` subagent) may write `profile.json`, `timeline.md`, `readiness.json`.

**Named exceptions:**
- `cancer-buddy-caregiver` may write `profile.caregivers[]` only (see [caregivers[]](#caregivers)).
- `cancer-buddy-comfort` (pro-skill) may write `profile.acp_status` only.

Any other sub-skill that wants to reflect new information (e.g. a new imaging study) must trigger an organize re-run, not mutate in place. A sub-skill writing any field outside its declared exception is non-compliant.

## Defensive reads

All consumers must tolerate missing optional fields — surface a prompt, do not crash. Missing required fields trigger the re-organize suggestion above.

## comfort symptom-log YAML schema

Standardized format for `patients/<patient_code>/reports/comfort/symptom-log/<YYYY-MM-DD>.md`. Written as a YAML code block inside the .md file.

```yaml
date: 2026-04-23
ecog: 3
pain:
  worst_last_24h: 6  # 0-10 NRS
  current: 3
  character: "dull, lower back, radiating left leg"
  relieved_by: "oxycodone 10mg q4h"
  breakthrough_doses: 2
dyspnea:
  at_rest: "none|mild|moderate|severe"
  on_exertion: "none|mild|moderate|severe"
  o2_use: true
nausea:
  episodes: 1
  vomiting: false
  trigger: "after breakfast"
delirium:
  present: false
  type: null        # hyperactive | hypoactive | mixed
  onset: null
secretions:
  terminal_rattle: false
affect:
  state: "withdrawn, tearful"
  notable: "said 'I want to go home' twice"
meds_today:
  - oxycodone 10mg q4h prn
  - ondansetron 8mg BID
  - lorazepam 0.5mg prn
family_observations: |
  Patient refused breakfast. Daughter stayed 6 hours.
  Grandchild video-called, patient smiled briefly.
logged_by: caregiver  # patient | caregiver | family
```

Single-writer assumption: one log entry per calendar date; concurrent writes by multiple family members are not supported (last write wins).

## Shared contract surface

The sections describing `reports/{mtb-lite,mtb-full,explore,manage}`, `acp_status`, the comfort `symptom-log`, and the `comfort/` report directory are the **shared contract incl. private pro-skill writers** (`cancer-buddy-comfort`, `cancer-buddy-mtb-lite`, `cancer-buddy-explore`, `cancer-buddy-manage` in `cancer-buddy-pro-skill`). Even though those skills are not shipped in this public bundle, their on-disk contract is defined here so public and private skills stay interoperable on the same `patients/` tree.

## Version pin

Declared tested against `vmtb-skill` ≥ 4.0.0-beta.6. Breaking schema changes bump the organizer's output first, this file follows.
