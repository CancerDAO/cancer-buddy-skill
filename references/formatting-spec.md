# Formatting Spec — Cancer Buddy Report Design System

> 本文件是 **权威设计规范**。`report_template.py` 的实现必须严格遵循此规范。
> Phase 2 Synthesis prompt 生成 `report_data.json` 时，只负责数据结构，不负责排版。
> 排版完全由 `report_template.py` 控制，不允许在 JSON 数据中夹带 HTML/CSS/markdown 格式字符。

## 四、加粗规则（Bold）

加粗**只用于**以下情形，不得滥用：

1. **节标题**（模块 1、模块 2……）
2. **患者信息块中的字段标签**（姓名、年龄……）
3. **异常检验值**（flag = high / low）
4. **建议补充项名称**（紧急/建议/已覆盖 后的项目名）
5. **表格表头**

加粗**禁止**用于：
- 普通叙述性正文
- 缺失字段的占位文字（如"未检测，建议完善"）
- 来源标注文字
- 页脚文字

## 五、表格编排规范

### 通用规则（所有表格）

- **表头行**：背景 `HDR_BG`（#D6E4F0），文字 `PRIMARY` 色，居中，9.5pt 加粗
- **数据行**：白底，9.5pt 常规字重，左对齐
- **异常行**（flag=high/low）：整行背景 `ALERT_BG`（#FCE8E8）；结果列文字 `ALERT_TEXT`（#C00000）加粗；结果值后追加 ` ↑` 或 ` ↓`
- **边框**：单线，颜色 `#D0D7DE`，宽度 0.5pt
- **行高**：表头 0.7cm；数据行自适应内容高度，最小 0.55cm
- **单元格内边距**：内置 Word 默认（上下 1mm，左右 1.5mm）

### 实验室指标表（add_labs_table）

列顺序和宽度（总宽 ≈ 15.5cm）：

| # | 列名 | 宽度（DXA） | 说明 |
|---|------|-----------|------|
| 1 | 日期 | 1400 | YYYY-MM-DD |
| 2 | 类别 | 1400 | 血常规/肿瘤标志物/凝血…… |
| 3 | 检验项目 | 2200 | 全称 |
| 4 | 结果 | 1600 | 数值+单位；异常加 ↑↓，红色加粗 |
| 5 | 参考值 | 1600 | 原始参考区间 |
| 6 | 临床意义 | 2200 | 一句话解读 |

### 分子检测表（add_molecular_table）

| # | 列名 | 宽度（DXA） | 说明 |
|---|------|-----------|------|
| 1 | 检测项目 | 2800 | 完整名称 |
| 2 | 结果 / 状态 | 2800 | 阳性/阴性/Pending（已送检，待回报）/未检测，建议完善/未取得 |
| 3 | 优先级 | 1100 | [关键] / [建议] / [参考]（对应 high/medium/low） |
| 4 | 临床意义 | 3700 | 一句话说明该指标的治疗决策相关性 |

行背景颜色规则：
- priority=high → `ALERT_BG` 行背景，优先级文字 `ALERT_TEXT`
- priority=medium → `WARN_BG` 行背景，优先级文字 `WARN_TEXT`
- priority=low → 白色背景，优先级文字 `OK_TEXT`

结果列：如状态含"未检测/未取得/Pending/待回报"，文字颜色改为灰色（#888888）

### 信息来源索引表（附录 C）

| # | 列名 | 宽度（DXA） |
|---|------|-----------|
| 1 | 模块 | 1800 |
| 2 | 数据点 | 3600 |
| 3 | 来源文件 | 4800 |

## 六、建议补充记录（Gaps）排版

三层结构，固定顺序（紧急 → 建议 → 已覆盖），各层标题行加粗，颜色对应 ALERT/WARN/OK：

```
【紧急】对后续分析至关重要（建议尽快补充）    ← 13pt 加粗 ALERT_TEXT
▸  [项目名]  —  [原因]                   ← 左缩进 0.5cm，项目名 10pt 加粗 ALERT_TEXT，原因 9.5pt 灰色

【建议】有助于提升分析精准度                  ← 10pt 加粗 WARN_TEXT
▸  [项目名]  —  [原因]

【已覆盖】已充分覆盖                           ← 10pt 加粗 OK_TEXT
▸  [项目名]  —  [原因]
```

各层之间的间距：`space_before = 8pt`。

---

## 七、节标题底线规范

一级节标题（`add_section_heading level=1`）在段落下方有一条分隔线：
- 颜色：`#2E75B6`（ACCENT 蓝）
- 宽度：`sz=12`（0.75pt）
- 与文字间距：`space=4`

二级小标题（`level=2`）无底线，文字色 `PRIMARY`，11pt 加粗。

---

## 八、患者信息块规范

位于文档最顶部，由外层单元格（浅蓝背景 INFO_BG）包裹：

1. **文档大标题**「病例总结报告」：18pt 加粗 PRIMARY 色，居中
2. **蓝色分隔线**（paragraph bottom border）
3. **4 × 4 内嵌表格**（4行4列，标签列背景 HDR_BG，内容列白色）
   - Row 1: 患者姓名 | 值 | 就诊医院 | 值
   - Row 2: 年龄/性别 | 值 | 临床诊断 | 值
   - Row 3: 采样/报告日期 | 值 | ECOG评分 | 值
   - Row 4: 病员号 | 值 | 病历编号 | 值

---

## 九、免责声明（页脚区域）

每份文件末尾、页码之前：
- 一条浅灰分隔线（`#CCCCCC`）
- 单段文字，8pt，灰色（#888888），居中
- 内容格式：`本报告由 Cancer Buddy 自动生成 | 生成时间：YYYY-MM-DD HH:MM | 分析文件数：N | 待确认 N · 建议核对 N · 已通过 N | 本报告不替代主诊医生的临床判断，所有治疗决策须与医生确认。`

---

## 十、禁止事项（强制）

以下内容**绝对不能出现**在任何生成文件中：

| 禁止内容 | 原因 |
|---------|------|
| readiness grade（A/B/C/D/F） | 内部路由字段，患者不需要看 |
| score 数字（如 32/100） | 同上 |
| "必写字段" / "条件字段" / "可选字段" | 内部 prompt 元语言，不属于患者文档 |
| sidecar 文件名（如 `.md` 内部路径） | 替换为"来源文件：XXX" |
| 任何 JSON / YAML 格式标记 | 文档是给人读的 |
