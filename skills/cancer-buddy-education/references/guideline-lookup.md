# 指南与标签的 answer-time 来源核验

治疗方案、线次、检测适应证、随访、疫苗、生育等待时间、剂量/给药、批准状态、
预后数字和法律结论都属于版本敏感内容。每次回答必须读取真实、适用且版本可核验的一手
来源；不能从模型记忆重建。

## 1. 可用来源

按主张类型选择最直接的来源，而不是套统一排名：

- 药物给药、禁忌、剂量调整和药物/食物相互作用：当前法域监管机构的完整标签；
- 癌种诊疗路径、检测与随访：当前专业学会或政府指南的原始页面/PDF；
- 批准、报销和安全公告：当前监管/支付机构官方页面；
- 临床试验：当前注册记录，必要时结合方案和原始论文；
- 法律/隐私：当前法规、主管部门文件和部署法域的合格专业复核；
- NCI PDQ 等证据综述可作背景，但不得自动标为专业学会指南。

检索工具 = 宿主当前可用的任意联网/数据能力：已装的 `web-access` skill（有则联网抓取优先经它）、
宿主原生 WebSearch/WebFetch、或任何相关的已装 MCP 工具。存在即用，不存在则换其它现行一手来源，
都不可用则按 §4 fail-closed；不假设、不硬依赖任何特定工具或 MCP。

用户或宿主明确提供、合法持有且版本可核验的现行指南文件可以作为本地一手来源（其落地形式见
§1.5 本地指南库）。记录
发布者、标题、版本/日期、页码/章节和受控来源引用。不要在主目录中广泛搜索私人文件，
也不要把主机绝对路径写入患者输出。若本地文件版本不清、过期、不适用或访问未获授权，
改查官方实时来源。

搜索摘要、转载、医院营销页、排名、模型记忆和未标版本的缓存不能支持当前临床结论。
付费/受许可来源须遵守适用条款和部署方的再分发政策：只呈现完成本次解释所需的最小内容；
不得默认复制或打包完整表格给第三方。权利不清时引用官方入口并生成待医生核对的问题。

## 1.5 本地指南库（可选，`CANCER_BUDDY_GUIDELINES`）

这是 §1「用户/宿主明确提供的本地一手来源」的落地形式，**默认关闭**；未配置时行为与今天完全一致
（只能手动递入单个文件）。

- **启用**：环境变量 `CANCER_BUDDY_GUIDELINES` 指向一个用户掌控、合法持有的指南目录（绝对路径）。
  未设置 = 不启用，跳过本节。
- **清单**：该目录下放 `index.json`，逐条登记 `file`（目录内相对路径）、`publisher`、`title`、
  `version`、`date`、`jurisdiction`、`cancer_types`、`license`。清单提供可核验的版本/出处元数据——
  **没有清单条目、或版本不清 / 过期的文件不作当前来源**，回退联网（符合 §1）。示例见
  [guideline-pack.example.json](guideline-pack.example.json)。
- **answer-time 顺序**（针对 §(b) 指南级主张）：① 已配置且清单存在匹配癌种/法域、版本可核验且
  未过期的条目 → 读该文件，脚注标 `〔资料库〕` 含出版者/标题/版本/页码；② 否则联网查官方一手
  来源 `〔联网〕`（用 §1 的可用工具）；③ 否则按 §4 fail-closed。
- **隐私 / 边界（硬）**：只读取解析后真实路径落在 `CANCER_BUDDY_GUIDELINES` 内的文件；拒绝越界
  符号链接与 `..` 穿越；**绝不**扫描主目录、患者目录或该目录以外任何位置；只读不写；患者输出
  永不出现主机绝对路径。§1「不要在主目录中广泛搜索私人文件」依旧有效——本功能只查用户显式
  指向的这一个目录。
- **许可**：遵守清单 `license` 与部署方再分发政策，只呈现本次解释所需最小内容，不默认打包完整
  付费表格给第三方。

## 2. 检索上下文

检索前明确癌种、组织学、来源报告中的分期/治疗意图、关键生物标志物、既往治疗、年龄或
妊娠场景、法域和查询日期。缺失字段保持 `unknown`；患者口述不能晋升为已核实分期、
ECOG、治疗线或疗效。

不同来源适用人群或建议不同时并列展示，不替患者选择。任何个人治疗适用性、剂量或是否
需要检测的决定交给主诊团队。

## 3. 原子化主张与引用

每条版本敏感主张分别记录：

```yaml
claim_text: 原子化断言
population: 适用人群与场景
jurisdiction: CN|US|EU|other
source_type: guideline|regulator_label|law|trial|systematic_review
source_title: 来源标题
source_url_or_controlled_ref: 直接 URL 或受控本地引用
version_or_date: 版本或日期
page_or_section: 本地/PDF 来源的页码或章节
accessed_at: YYYY-MM-DD
applicability_limits: 不适用条件
```

同时遵守根目录 `references/clinical-content-governance.md` 的人类签审与到期规则。一个脚注
不能替多条不同主张背书，引用必须出现在患者可见输出中，而不只是内部落盘文件。

患者输出中的脚注编号从 1 连续递增、无缺口，内联编号与文末清单一一对应。每条脚注标记
来源类型：`〔档案〕`、`〔资料库〕`、`〔联网〕` 或 `〔文献〕`。本地指南脚注显示发布者、
标题、版本和页码，不显示主机绝对路径；联网脚注显示直接 URL 与访问日期。

## 4. 失败关闭

本地来源、网络、登录、版本或原始页面不可用时：

- 明确说明本次无法核实的具体主张；
- 不输出基于模型记忆的具体方案、线次、检测、随访间隔、剂量、审批状态、预后数字或法律结论；
- 只提供不依赖版本的概念解释，并生成一条带给主诊团队的问题；
- 将相关 `patient_facing_allowed` 设为 `false`。

失败关闭不是静默丢失：保留已验证的其他原子主张，并清楚标出未完成部分。

## 5. 出稿前门禁

- `G-SOURCE`：每条版本敏感主张都能回到真实来源、版本和适用人群；
- `G-NO-MEMORY`：模型记忆不充当指南、标签、预后、批准或法律来源；
- `G-NO-VERDICT`：不生成个人分期、疗效、预后数字、换线或检测决定；
- `G-CITE`：脚注连续、类型标签齐全、内联与清单完全对应；
- `G-COPYRIGHT`：仅输出目的所需内容，遵守许可与再分发限制；
- `G-DISCLOSURE`：viewer 只能看到其获授权的患者资料；有能力患者对自身信息的明确请求不被家属偏好覆盖；
- `G-EXPIRY`：过期或版本不明的主张不进入患者输出。
