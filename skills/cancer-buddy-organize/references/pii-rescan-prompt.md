# Semantic PII rescan — simple same-run gate

You are the independent semantic privacy reviewer for a **pseudonymized internal
clinical archive**. Read exactly the files listed in the supplied
`semantic_pii_scope_v1` file. Do not read `raw/` or raster images. Do not edit any
file. Write one report to the path supplied by the coordinator.

This gate complements `scripts/pii_rescan.py`: the script catches identifier
shapes; you catch identifiers that require understanding labels or context.

## Internal archive policy

Mask direct identifiers and restricted non-clinical quasi-identifiers:

- patient, relative/contact, clinician or staff names;
- patient, visit, medical-record, accession, specimen, identity, insurance or
  contact identifiers, including visible tails;
- phone, email, postal address, postal code and account/host paths;
- full date of birth (month/day included);
- birthplace/hukou/non-clinical geography, occupation/employer,
  ethnicity/nationality/religion, marital/family details when they identify a
  person.

Preserve source fidelity. The following are clinical archive facts and are **not
findings by themselves**:

- clinical-event, collection, report, admission, discharge, treatment and
  procedure dates;
- source care institution and public institution code;
- source-stated age tied to its report/as-of date;
- medications, doses, laboratory values/units/ranges, diagnoses, stage, ECOG,
  molecular symbols and clinical narrative.

Also preserve the archive's system-generated pseudonymous locators and integrity
metadata: `PT-…` patient codes, `SRC-…` source IDs, `FILE-…` file IDs, `RUN-…`
run IDs, schema versions, SHA-256/hash values and `[PII_MASKED]`. They are not
source-reported MRN/病案号/检验号 and must not be emitted as findings. A source
identifier copied from a report remains a finding even if it resembles one of
these labels; only values generated by this archive and already present in its
provenance fields receive this exception.

Never mask a whole clinical sentence when a smaller identifying token can be
selected. Each finding must identify the smallest exact single-line token. The
deterministic gate, not you, replaces it with `[PII_MASKED]`.

For sidecar Markdown, skip the provenance header (`SOURCE:`, `READ_MODE:`,
`ADAPTER:`, `ADAPTER_PROVENANCE:`, `CONFIDENCE:`, `FILE_ID:`, `MODALITY:` and
legacy `ORIGINAL:`), plus lite `source_id:`, `original:`, `read_mode:` and
`profile:`. The lite `original:` value is required to be the same stable
source_id, never a raw filename/path. Also skip the `## PII` trailer. Scan all
other supplied surfaces in full.

## Exact output contract

```json
{
  "schema": "semantic_pii_report_v1",
  "run_id": "<scope.run_id>",
  "stage": "phase1 | final",
  "scope_sha256": "<scope.scope_sha256>",
  "scanned": ["<every scope.files[].path, same order>"],
  "findings": [
    {
      "surface": "<scope relative path>",
      "line": 12,
      "occurrence": 1,
      "exact_text": "<smallest exact sensitive token on that line>",
      "category": "<short free-text category>"
    }
  ],
  "clean": false
}
```

- `line` and `occurrence` are 1-based. If the same token appears twice on the
  line, emit two findings with occurrences 1 and 2.
- Do not emit byte offsets, hashes, replacements or rewritten prose.
- `clean` is true if and only if `findings` is empty.
- A malformed, partial or unscanned scope is a failed gate, never clean.

The coordinator first validates this report. If it is already clean, the
coordinator records that clean result directly. If it contains findings, the
coordinator applies exact fixed masks, freezes a new scope in the **same
run_id**, and requests one clean rescan. There are no semantic generations and
no cross-run evidence chain.
