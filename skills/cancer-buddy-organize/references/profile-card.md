# Profile Card

Profile Card 是资料索引，不是临床画像或决策面板。

## 可显示

- 患者选择的非临床别名和档案更新时间；
- 报告中明确写出的诊断、组织学、分期、治疗事件和日期，逐项附来源；当前治疗连同依据显示（`latest_status.status_basis`：
  给药记录 / 当次医生记录 / 申请单指征 / 家属或本人陈述），未注明日期的家属陈述显示为“家属陈述（未注明日期）”，
  不配日期；
- 医生明确记录的 ECOG/疗效（如有）；医生书写的体能状态原文（如“PS=2（2030-01-05）”），按原文标签显示，
  不换算成 ECOG；
- 报告原文写明的急性/附带发现（`acute_findings.json`）：逐字（`label` / `verbatim_text`，不写类名）、带日期与来源，
  emergent/urgent 条目放在最前，并提示尽快告知治疗团队；不解释病因、不评估严重程度；
- 患者功能/症状描述，单独标 `patient_reported`；
- 冲突、缺失、缺页、资料时效、OCR 和待人工核对状态。

“🔍 待人工确认”取自 `readiness.json.review_flags[]`，按 `severity`（red → yellow → info）排序，组内按
`kind` 归类（字迹不清 / 版面异常 / 文书删改 / 来源不一致 / 缺页与资料时效 / 其他）。这里的 `severity`
是**整理时读取与档案完整性的不确定程度，不是临床严重度**：red 表示该字段在得到更正来源或临床人员
核实前不能当作已确认值使用，与病情轻重无关。卡片上用“需核对程度”之类的说法，不用“严重”。

## 禁止

- 推断 ECOG、疾病状态、器官限制、疗效、预后或治疗路径；
- 通用红黄绿临床严重度（上面按 `severity` 排序的是抽取不确定程度，不是病情分级）；
- 模型“建议值”和“接受建议后更新”；
- 把 patient_code 当身份验证；
- 将患者自述与正式报告合并成一个看似已确认的字段。

冲突卡只提供“查看来源/上传正式更正/请临床人员核对”，不提供选择一个值成为真值。

**时变字段不进冲突卡。** 年龄、体重、身高、ECOG、`current_status.*` 在不同来源日期取值不同是时间演变，按时间序显示（各值带自己的 `_as_of`），不产生冲突卡、不要求患者去"核对"——判据见 `organizer-prompt-phase2-synthesis.md` §2.1。年龄显示必须带其 `age_as_of` 日期；只有同日期矛盾或年龄倒退这类与时间跨度冲突的情况才升级为冲突卡。
