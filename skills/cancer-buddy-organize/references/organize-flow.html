病历整理完整流程

当前版本的核心思路是：LLM 负责读取、脱敏判断和定位；脚本负责确定性打码、校验和提交。最终包只有在 MD、JSON、HTML 和源文件副本都通过脱敏 gate 后才可持久化。

[M] 理论上必然发生 [C] 条件触发 [O] 可选或后续模式 [G] 不通过就不能进入下一阶段

主线流程

[M] 1. 接收输入

Resolve input

  • 用户提供文件夹、单文件或压缩包。
  • 压缩包先解到 /tmp。
  • 确定 patient_dir 和 11 个桶目录。
[M] 2. 切片编排

Plan slicing

  • 统计文件和子目录。
  • 大批量图片按 worker 切片。
  • 保证每个源文件都会进入 Phase 1。
[M] 3. LLM 读取

Phase 1 ingestion

  • 复制明文源文件到本地 10_原始文件/ staging。
  • adapter 只把文件变成 LLM-readable input。
  • LLM 输出脱敏 MD sidecar。
  • LLM 输出无明文的 pii_regions locator。
[G] 4. MD 脱敏复扫

PII rescan

  • pii_rescan.py 扫所有 sidecar。
  • 发现残留 PII 就回 Phase 1 修。
  • 通过后才允许进入 Phase 2。
[M] 5. 综合整理

Phase 2 synthesis

  • 读全部脱敏 MD。
  • 语义分类到 11 个桶。
  • canonical rename。
  • 源文件 copy 和 MD co-located。
  • 生成 inventory、manifest、structured JSON。
[M] 6. 展示与摘要

Review + HTML

  • 展示 review_summary.md。
  • 展示 profile card。
  • 生成 病情简要总结.html。
  • HTML 只读脱敏 JSON/MD。

持久化前的源文件本体脱敏

[M for persist]

prepare

  • 读取 redaction_manifest_v2。
  • 按 LLM locator 生成 redacted candidate。
  • 不覆盖原件，不删除原件。
[G]

coverage gate

  • locator 合法。
  • region 已覆盖。
  • candidate 可打开。
  • hash 与原件不同。
[G]

LLM QA gate

  • LLM 只看 redacted preview/payload。
  • 输出 llm_redaction_qa.json。
  • 报告只含 file id、pass/fail、类别。
[M for persist]

commit

  • 只有 coverage + LLM QA 都 pass 才执行。
  • 替换 bucket source copy。
  • 替换 10_原始文件/ mirror。
  • 明文原件被覆盖删除。

最终验收门

[G] final package gate

validate_structured_outputs.py

结构化数据 schema 校验，source_refs anchors 必须能解析。
MD 无 PII 再次运行 sidecar PII residue scan。
source redaction hard gate 每个 persisted source 必须 done + coverage_passed + llm_qa_passed + qa_passed + original_deleted。
HTML 无 PII validate_case_summary_html.py 校验模板 provenance、shape、无精确年龄和身份信息。
[M] ready state

最终可持久化包

  • 桶内源文件是 redacted copy。
  • MD、JSON、HTML 都来自脱敏输入。
  • 10_原始文件/ mirror 也已替换为脱敏版本。
  • blocked / failed / pending 的源文件不能进入最终包。

条件分支

[C] continuation

Phase 1 没跑完

  • worker 上下文满或文件未处理完。
  • 只续跑剩余文件。
  • 完成后回到 Phase 2。
[C] coverage retry

Phase 2 发现缺 sidecar

  • 列出 missing files。
  • 派 mini Phase 1 补齐。
  • 重新跑 Phase 2。
[C] 段E relevance gate

发现非医疗文件

  • high-confidence unrelated: 进入 99_无关文件/high_confidence。
  • borderline: 进入 99_无关文件/uncertain。
  • 高置信无关文件可 no-confirm 自动删除；borderline 不自动删。
[C] blocked unsupported

源文件无法可靠脱敏

  • MD/JSON/HTML 可以继续生成。
  • 该源文件标记 blocked。
  • 最终 persist gate 不会允许它进入包。
[C] review flags

发现可疑字段

  • 生成并展示 review_flags.md。
  • 红色 flag 未确认时阻止下游 skill。
  • 用户确认后写回 resolution。
[C] HTML gate fail

HTML 校验失败

  • 不允许声明摘要完成。
  • 回到 data/template 渲染修复。
  • 不手写 HTML 绕过模板。

可选或后续模式

[O] conversation_incremental

聊天中补充事实

  • 不是首次整理主流程。
  • LLM 提取候选事实。
  • 用户确认后才写 formal fields。
  • source ref 使用 conversation anchor。
[O] upload_reconciliation

已有档案后重新上传

  • LLM 判断 new / supersede / conflict。
  • 替换、并存、忽略都要确认。
  • supersede 是归档旧文件，不静默删除。
[O] downstream skills

整理后进入下游

  • 例如 education、nutrition、second-opinion。
  • 前提是 profile、readiness 和 red flags 已处理。
  • 下游只读整理后的脱敏产物。

一句话判断

核心不变量
LLM 做判断：读取、转写、PII 判断、坐标/结构 locator、QA。
脚本做确定性动作：打码、替换、hash/coverage 校验、HTML 渲染、最终 gate。
明文不出本地 staging：最终包不能包含未脱敏源文件。
删除必须双通过：coverage_passed && llm_qa_passed && qa_passed 后才覆盖明文原件。
