# bias-disclosure.md — 个案报告偏倚披露（本 skill 的头号安全资产）

这是 `cancer-buddy-case-precedent` 最重要的安全文件。它规定了：**如何诚实地披露个案报告（case report）作为证据的系统性弱点**，让患者和家属永远不会把「文献里某个人这样治好了」误读成「我也会这样」。

所有文案块都是 **copy-paste-ready 的中文（zh）**。落到非中文 locale 时，**渲染的是这些文案的「含义」到 `profile.json.locale`**（见 `../../references/i18n.md`），临床实体（药名/基因/变异/TNM/分期/数值+单位/PMID/期刊名）逐字禁译（见 `../../references/safety-guardrails.md` → 临床实体禁译）。

对应 SKILL.md 的 P0 门：**G-BIAS / G-N / G-NO-AGGREGATE / G-TIER**。任何一条违反即 bug。

---

## 1. 为什么个案报告是有偏的（必须让用户理解的底层事实）

个案报告之所以被写出来、被期刊接收发表，恰恰是因为它**不寻常**——疗效特别突出（"惊艳缓解"）、病理罕见、或用了新颖/非标准的方案。**发表偏倚 + 幸存者偏倚**共同、系统性地把「可见的文献」拉向乐观的一端：治好的、活得久的、反应好的更容易被写成论文；失败的、进展的、去世的极少被写下来，更极少被发表。

因此可见的个案 **不是一个有代表性的样本**，而是被筛选过的、偏乐观的一小撮。**它们不能被当作预后来读**——一个真实患者用某方案获得长缓解，不代表这是常态，更不代表你会重现同样的结局。

> 一句话内核：**个案报告告诉你「有可能发生过什么」，不告诉你「多大概率会发生在你身上」。**

---

## 2. 两种呈现方式（对齐 G-PATIENT-FIRST 的两层输出）

偏倚披露有两种形态，**别混用**：
- **§A 患者版 = 轻编织进正文一句**（见 2a），**不砌顶部墙**——给一个害怕的家属砌一堵免责墙是冰冷的，honesty 是对的但开场就砌墙、语气错了。
- **§B 医生版临床附录 = 顶部完整横条 + 显式 N**（见 2b），给医生看的严谨版才用横条。

### 2a. 患者版：轻编织（§A `相似病例_我可以问医生的.md`）

不在顶部砌墙。把偏倚**编织进正文一句话**，紧跟"我去翻了相似病例"之后、列治疗方向之前。canonical 文案（zh，可直接用）：

> 先说清楚：这些都是零散的个案、因为少见才被写下来，**代表不了大多数人、也预测不了你**——所以下面是**去和医生讨论的线索**，不是答案。

患者版规则：**不逐例摊结局、不放死亡/急速恶化个案卡片**（单个坏结局是偏倚小 N 的惊吓噪音，既非真希望也非诚实预后）；N 不必喊在最前（避免"34 个人像我"的过度信号），需要精确 N 时指向 §B。

**可点来源例外（放宽点，与"不砌墙"并存）**：患者版每个**治疗方向**后面**允许挂一条可点 PMID 来源**（`来源：[PMID <pmid>](https://pubmed.ncbi.nlm.nih.gov/<pmid>/)`，每方向 ≤1 条），让患者/医生能一键核对、带去问医生。这**不等于**砌偏倚墙或摊结局——PMID 只是"可核验的出处锚"，逐例结局 / 6 维表 / 顶部横条仍只在 §B。PMID 逐字（临床实体禁译）。此点刻意把旧口径的"患者版零 PMID"改为"每方向一条可点来源"：目标是可核验且不冰冷。

### 2b. 医生版：顶部横条（§B `PRECEDENTS_临床附录.md`）

给医生看的严谨附录**才**在最顶部、正文之前渲染下面这段横条，且**必须带显式 N**（命中的个案数、含去重计数）。这是 G-BIAS + G-N 的合并落点。

**中文（zh）canonical 文案 — 直接复制：**

```
> ⚠️ 先读这里：关于下面这些病例能说明什么
>
> 下面是文献里检索到的 **N=<命中数> 例**与你情况相似的**真实个案报告**。请带着下面几点来读它们：
>
> - **它们因罕见或疗效突出才被发表** —— 治好的、反应特别好的更容易被写成论文，失败和去世的极少被写下来。
> - **所以这些病例系统性偏乐观**，不是一个有代表性的样本，**不能代表和你相似的所有人**的真实情况。
> - **这不是对你预后的预测** —— 别人的结局不会因为写进了论文就更可能发生在你身上。
> - **这只是「去研究、去和医生讨论」的线索**，不是治疗建议，也不替你判断该怎么治。
> - 请把这份清单**带给你的主诊医生一起看**。
```

**渲染规则：**
- `<命中数>` 用 Step 2 去重 + 撤稿剔除后的**真实命中数**填入（例如 `N=3`）。N=0 时不渲染横条，改出「未找到相似个案」的诚实空态（见 SKILL.md Step 2）。
- 横条**置顶**，在任何病例卡片之前；不得折叠进 `<details>`，不得挪到脚注。
- 非中文 locale：把上面每一条的**含义**译到 `profile.json.locale`；`N=<数>`、PMID、临床实体逐字保留。

## 3. 每条病例携带的偏倚标签（per-case bias tag）

除了顶部横条，**每一张病例卡片**内都必须带一行短标签，防止用户只看单条时丢掉语境：

**中文（zh）canonical 文案 — 直接复制：**

```
🔸 单个已发表个案，因不寻常才被记录 —— 是线索，不是概率，不是你的预后。
```

- 每条都带，不因为顶部已有横条就省略（用户常只截图/只读某一条）。
- 语气克制、中性；`disclosure_state == "suppressed"` 时同样保留此标签（它不含晚期/生存期等情绪词，见 SKILL.md Disclosure 行为）。

---

## 4. G-N 规则 —— 永远显式标 N，小 N 禁频率语

**永远显式显示 N**（命中个案数），并让它出现在顶部横条里。N 小的时候（**指导阈值：N ≤ 5**）尤其危险，因为任何"倾向性"表述都会被误读成统计规律。

**当 N ≤ 5：绝不使用任何暗示频率/普遍性的措辞，只陈述原始计数。**

- ❌ 禁：「**大多数**病例……」「**很多**病例……」「**通常**会……」「**往往**……」「一般来说……」「多数患者……」
- ✅ 允许（原始计数式）：「在找到的 **3** 例中，**2** 例……」「**3** 例里有 **1** 例记录到……」「这 **3** 例分别用了 A / B / C。」

**规则要点：**
- 把「几分之几」说成**具体的分子/分母**，绝不外推成比例或概率。
- N 大（>5）也不豁免 G-NO-AGGREGATE（第 5 节）——计数可以，算「率」永远不行。
- 逐维相似度里同理：「6 维中命中 4 维」是计数，OK；「相似度 80%」是伪聚合，禁。

---

## 5. G-NO-AGGREGATE 规则（硬门）—— 绝不把个案聚合成任何"率"

**这是最硬的一条。绝不**跨病例计算或陈述：生存率、有效率（ORR）、缓解率、疾病控制率、中位生存（mOS/mPFS）、任何百分比、任何统计量、任何"平均/中位"。**个案是轶事，N=3 的轶事推不出统计结论**——任何"率"都会制造出这批病例根本不具备的确定性。

**被禁的措辞（BANNED）vs 允许的逐病例事实措辞（ALLOWED）：**

| ❌ 禁（聚合/统计） | ✅ 允许（逐病例事实） |
|---|---|
| 「3 例中 2 例缓解，**有效率 67%**」 | 「找到的 3 例中，2 例记录到 PR，1 例记录到 PD（逐例见下）。」 |
| 「用该方案的病例**中位生存 18 个月**」 | 「例①随访 18 个月仍存活；例②在 6 个月时记录到进展；例③未报告随访时长。」 |
| 「**大多数**类似患者对 osimertinib 有反应」 | 「这 3 例中，2 例使用 osimertinib，best response 分别为 PR、SD。」 |
| 「**缓解率约 50%**」「**预后较好**」 | 「例① CR、例② PD —— 两例结局不同，各自见引文。」 |
| 「**平均**起效时间 2 个月」 | 「例①记录 2 个月起效；其余 2 例未报告起效时间。」 |

**规则要点：**
- 逐病例陈述**每一例各自发生了什么**，用 `例①/例②…` 或 PMID 锚定，配逐字引文；**不横向汇总成一个数字或一个形容词**（"预后较好""疗效可观"同样是被禁的隐性聚合）。
- 抽不到的字段标「未报告」，不用别的病例去补（那也是聚合）。
- 若用户直接追问"那到底有效率多少 / 能活多久"：**拒绝计算**，用一句话解释为什么不能（本节内核 + 第 1 节偏倚），并把问题引回主诊医生。

## 6. G-TIER 规则 —— 整份输出标注为最弱证据

整份 PRECEDENTS.md 必须在顶部横条附近**显式标注证据层级为最弱**：

**中文（zh）canonical 文案 — 直接复制：**

```
📉 证据等级：个案报告属于**最弱一档证据（证据层 C→D）** —— 低于临床试验、低于诊疗指南。
它能提示「有人试过、发生过什么」，但不能证明「有效」或「适合你」。
```

- 交叉引用 house 的 **Evidence grading A–D**（`../../references/safety-guardrails.md` → Evidence grading）：
  - **A** = III 期 RCT / 指南（NCCN/CSCO/ESMO）
  - **B** = I–II 期试验
  - **C** = 回顾性 / 病例系列（case series）
  - **D** = 临床前 / 专家意见
  个案报告落在 **C→D** 区间，**明确低于 A（试验/指南）**。任何时候都不得把个案与试验/指南并列成"同等证据"。
- 与顶部横条、per-case tag 一起，构成"这是线索、不是结论"的三重冗余提示。

---

## 7. Canonical 免责 footer（每份清单末尾必现）

末尾**必须**渲染 house canonical 免责的含义 —— 基座是 **`不替代主诊医生的判断`**（`../../references/safety-guardrails.md` → Always say / Canonical clause；医生术语一律 **主诊医生**，不得改成主治医师/主管医生），并接上本 skill 专属的 **非预后 / 非治疗建议** 尾巴。

**中文（zh）canonical footer — 直接复制：**

```
> 这些是有文献记录的真实病例，**不替代你主诊医生的判断**，不是对你结局的预测，也不是治疗建议。
> 个案报告往往因罕见或疗效突出才被发表，系统性偏乐观、不代表总体。
> 请把这份清单带给你的主诊医生一起看，任何治疗决策都必须与主诊医生确认。
```

- 基座 clause `不替代主诊医生的判断` **不得被删弱或软化**；只允许在其后**追加**本 skill 的尾巴（非预后 / 非治疗建议 / 带给主诊医生）。
- 非中文 locale：渲染上面文案的**含义**，`主诊医生` 对应术语按 locale，但核心 clause 与"非预后/非建议"语义必须保留。

## 8. 落地 checklist（生成 PRECEDENTS.md 时逐条自检）

- [ ] **G-BIAS** — 顶部偏倚横条已渲染，置顶、未折叠。
- [ ] **G-N** — 横条带显式 `N=<真实命中数>`；N ≤ 5 时全文无「大多数/很多/通常」等频率语，只有原始计数。
- [ ] **每条** per-case bias tag 已带（第 3 节）。
- [ ] **G-NO-AGGREGATE** — 全文零"率"、零中位、零百分比、零"预后较好/疗效可观"类隐性聚合；逐病例各自陈述。
- [ ] **G-TIER** — 已标注证据层 C→D，明确低于试验/指南，交叉引用 A–D 分级。
- [ ] **免责 footer** — 末尾含 `不替代主诊医生的判断` + 非预后/非治疗建议尾巴。
- [ ] 非中文 locale：以上全部渲染为 locale 的含义；PMID + 临床实体逐字未译。
